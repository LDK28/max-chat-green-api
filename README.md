# MAX Chat · GREEN-API

Адаптивный веб-клиент MAX на React + TypeScript + Vite, работающий через GREEN-API.

## Возможности

- Подключение по `apiUrl`, `idInstance`, `apiTokenInstance` с проверкой `GetStateInstance`.
- Создание чата по международному номеру телефона через `CheckAccount`.
- Отправка текстовых сообщений методом `SendMessage`.
- Приём входящих сообщений через `ReceiveNotification` (long polling).
- Подтверждение обработанных уведомлений через `DeleteNotification`.
- Обработка ошибок и повторная отправка сообщений.
- Адаптивный интерфейс для desktop и mobile.

## Локальный запуск

### Требования

- Node.js 20 или новее.
- npm.
- Авторизованный MAX-инстанс в GREEN-API.

### Установка и запуск

Клонируйте репозиторий:

```bash
git clone https://github.com/LDK28/max-chat-green-api.git
cd max-chat-green-api
```

Установите зависимости:

```bash
npm install
```

Запустите dev-сервер:

```bash
npm run dev
```

Vite выведет локальный адрес приложения в терминале. Обычно это `http://localhost:5173`.

После открытия приложения в браузере введите:

- API URL;
- ID Instance;
- API Token Instance.

Значения можно получить в личном кабинете GREEN-API после создания и авторизации MAX-инстанса. Credentials не нужно добавлять в исходный код или `.env`: приложение запрашивает их через интерфейс и хранит только в памяти открытой вкладки.

### Проверки

```bash
npm run lint
npm run test
npm run build
```

Production-сборка будет создана в каталоге `dist/`.

Перед публикацией приложение также было проверено вручную на реальном MAX-инстансе: сообщения успешно отправляются и принимаются.

## Настройка GREEN-API

Создайте инстанс для MAX в [личном кабинете GREEN-API](https://console.green-api.com/), авторизуйте его и скопируйте API URL, ID и токен в форму приложения. В настройках инстанса включите `incomingWebhook` и оставьте `webhookUrl` пустым для HTTP API polling.

Уведомления поступают в **общую FIFO-очередь инстанса**. Не запускайте несколько конкурирующих получателей одного инстанса. После получения уведомления клиент удаляет его из очереди независимо от типа и отображает только входящий текст.

Секреты не находятся в репозитории и хранятся только в памяти вкладки; после перезагрузки страницы нужно подключиться снова. При этом браузерные запросы позволяют владельцу вкладки видеть токен в инструментах разработчика. Это демонстрационный клиент, не предназначенный для изоляции секретов нескольких пользователей.


## Архитектура

- `src/api/greenApi.ts` — типизированный транспорт GREEN-API.
- `src/lib/chat.ts` — валидация номера, преобразование событий и дедупликация.
- `src/App.tsx` — экраны, локальные сообщения и подписка на входящие.
- `src/styles.css` — адаптивная стилизация без тяжёлой UI-библиотеки.

### Ограничения MVP

Сообщения и список чатов не переживают обновление страницы. Входящая FIFO-очередь общая, поэтому сообщения других чатов также читаются текущим клиентом. В случае недоступности API клиент повторяет попытку с задержкой. При отключении отменяется текущий long-poll запрос.

Для промышленного использования потребовались бы серверное хранение, защищённый proxy, централизованная обработка очереди, история сообщений и управление несколькими пользователями.
