# MAX Chat · GREEN-API

Адаптивный клиент MAX на React + TypeScript + Vite для тестового задания.

## Возможности

- Подключение по `apiUrl`, `idInstance`, `apiTokenInstance` с проверкой `GetStateInstance`.
- Создание чата по международному номеру телефона через `CheckAccount`, получение настоящего MAX `chatId`.
- Отправка текстовых сообщений методом `SendMessage`.
- Приём входящих текстовых уведомлений через `ReceiveNotification` (long polling) и подтверждение каждого через `DeleteNotification`.
- Минималистичный UI, мобильная адаптация, обработка ошибок, повторная отправка.

## Настройка GREEN-API

Создайте инстанс для MAX в [личном кабинете](https://console.green-api.com/), авторизуйте его и скопируйте API URL, ID и токен в форму приложения. В настройках инстанса включите `incomingWebhook` и оставьте `webhookUrl` пустым для HTTP API polling.

Уведомления поступают в **общую FIFO-очередь инстанса**. Не запускайте несколько конкурирующих получателей одного инстанса. После получения уведомления клиент удаляет его из очереди, независимо от типа, и отображает только входящий текст.

Секреты не находятся в репозитории и хранятся только в памяти вкладки; после перезагрузки страницы нужно подключиться снова. При этом браузерные запросы позволяют владельцу вкладки видеть токен в инструментах разработчика. Это демонстрационный клиент, не предназначенный для изоляции секретов нескольких пользователей.

**CORS:** прямые запросы браузера должны быть разрешены сервером вашего инстанса GREEN-API. Если при тестировании обнаружится блокировка по CORS, понадобится прокси-сервер (например, в Yandex Cloud Functions), сохраняющий токен на серверной стороне.

## Размещение в Yandex Cloud

Выполните `npm run build` и загрузите содержимое папки `dist/` в Object Storage bucket с включённым статическим хостингом. Главная страница: `index.html`. Приложение использует один URL и не нуждается в SPA rewrite.

## Архитектура

- `src/api/greenApi.ts` — типизированный транспорт GREEN-API.
- `src/lib/chat.ts` — валидация номера, преобразование событий и дедупликация.
- `src/App.tsx` — экраны, локальные сообщения, подписка на входящие.
- `src/styles.css` — адаптивная стилизация без тяжёлой UI-библиотеки.

### Ограничения MVP

Сообщения и список чатов не переживают обновление страницы. Входящая FIFO-очередь общая, сообщения других чатов также читаются текущим клиентом. В случае недоступности API клиент повторяет попытку с задержкой. При отключении отменяется текущий long-poll запрос. Для промышленного использования нужно серверное хранение, защищённый proxy, централизованная обработка очереди, история и управление несколькими пользователями.
